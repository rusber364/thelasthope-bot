## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Офицеры хотят создавать реги как в Raid-Helper: после /raid create бот уводит в личные сообщения и по шагам спрашивает название, описание, дату, время и картинку, вместо длинной строки параметров в одной команде.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 /raid create (с необязательными каналом, размером и ролью для пинга) отвечает, что продолжим в личке, и бот пишет первый шаг; если личка закрыта — понятное сообщение и подсказка про /raid quick
- [x] #2 Шаги по порядку: название, описание (можно пропустить), дата (текстом или кнопками ближайших дней), время (текстом или кнопками), картинка (файлом или стандартный фон); на каждом шаге есть «Назад» и «Отмена»
- [x] #3 Неверная или прошедшая дата/время — бот объясняет и спрашивает снова
- [x] #4 В конце — предпросмотр реги и кнопки «Опубликовать», «Изменить» (любой шаг) и «Отмена»; публикация создаёт регу в выбранном канале с картинкой и пингом роли
- [x] #5 Своя картинка реги сохраняется и не пропадает при перерисовке реги; у остальных рег — прежний общий фон
- [x] #6 Черновик переживает перезапуск бота; новый /raid create заменяет незаконченный; старые черновики истекают
- [x] #7 Прежнее создание одной командой доступно как /raid quick; руководство и чек-лист обновлены
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. db: таблицы raid_drafts (черновик на человека, шаг, поля, картинка BLOB, промпт, updated_at) и raid_images (своя картинка реги).
2. raids/drafts.ts — хранение черновиков; store: saveRaidImage/getRaidImage; render/service: картинка реги вместо общего фона (в т.ч. при перерисовке).
3. raids/wizard.ts: чистая логика шагов (applyText, подсказки и кнопки), отправка шагов в личку, обработка сообщений в ЛС (по очереди на человека), кнопки rwiz:* (пропуск, назад, отмена, дата/время кнопками, стандартный фон, изменить, опубликовать), предпросмотр и публикация с проверкой прав.
4. index.ts: интент DirectMessages и Partials.Channel; interactionCreate: кнопки мастера в личке.
5. /raid create → мастер (channel/size/ping); /raid quick — прежнее создание.
6. Тесты: логика шагов и сквозной сценарий; документация, чек-лист; pnpm deploy — пользователю.
<!-- SECTION:PLAN:END -->
