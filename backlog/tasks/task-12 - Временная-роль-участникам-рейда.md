## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Чтобы открыть записавшимся доступ к каналам рейда или упоминать только их, нужна роль, которая сама снимается после рейда (Raid-Helper Premium).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 При записи выдаётся роль, при отписке снимается
- [x] #2 Через N часов после начала рейда роль снимается у всех
- [x] #3 Роль и N настраиваются в админке
- [x] #4 Снятие работает и после перезапуска бота
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Настройки raids.tempRoleId и raids.tempRoleHours (по умолчанию 3 ч) + проверка значений
2. Колонка raids.role_cleaned; запросы: реги, где пора снимать роль (отменённые или старт + N часов), и «есть ли у игрока другая активная рега»
3. src/raids/tempRole.ts: выдать роль при записи, снять при отписке (если нет другой активной реги), снять у всех участников по сроку
4. Вызовы из кнопок реги и тик планировщика (состояние в базе — переживает перезапуск)
5. Админка: выбор роли и часов на странице «Расписание рег»
6. Тесты: запросы, обработчик кнопок, чистка по сроку; документация
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Реализовано: настройки raids.tempRoleId/tempRoleHours (1–48 ч, по умолчанию 3) с выбором в админке («Расписание рег»), колонка raids.role_cleaned, запросы raidsDueForRoleCleanup и hasOtherActiveSignup, модуль src/raids/tempRole.ts (выдача при первой записи, снятие при отписке, если нет другой активной реги, чистка по сроку и при отмене в тике планировщика; отметка в базе ставится после снятия — при сбое чистка повторится после перезапуска). Проверено тестами: tempRole.test.ts (выдача/снятие через настоящий обработчик кнопок, сохранение роли при второй записи, снятие по сроку и при отмене, повторный тик ничего не трогает), тест админки на сохранение роли и часов. В живом Discord не проверялось.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Временная роль рейда: выдаётся при записи, снимается при отписке и через N часов после начала (или сразу при отмене); роль и N выбираются в админке. Чистка идёт по состоянию в базе на каждом тике планировщика, поэтому переживает перезапуск. Проверено: 103 теста, в т.ч. tempRole.test.ts и тест админки.
