## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->

2. admin-ui: pnpm-workspace, Vite+, React, Tailwind, shadcn/ui, lucide; тема (тёмная + переключатель), каркас с меню, вход/нет доступа, API-клиент (CSRF), Главная.

5. Бот раздаёт admin-ui/dist, старые HTML-страницы удаляются, документация и VPS-инструкция (pnpm build).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Этап 1: JSON API готов — /me, /overview, /options, /settings (+ PUT по 10 разделам с проверкой каналов/ролей и validateSettings, запись в лог-сервер, побочные действия: сверка голосовых ролей, список рейдов, закрепы, автоочистка), пробные отправки, оформление, опросы (шаблон, проверка, публикация multipart, итоги с ответами по людям, CSV, копия, закрытие), посещаемость, создание реги из шаблона. Вход: та же сессия; 401/403 JSON; CSRF — заголовок X-CSRF-Token. apiTypes.ts без импортов, совпадение с типами бота проверяет компилятор (settingsJson, satisfies). Тесты: api.test.ts (8), всего 181/181.

Этап 2: каркас admin-ui (pnpm-workspace). Vite+ 1.3 (vp dev/build/check; vite → @voidzero-dev/vite-plus-core, vitest 5.0.5 через overrides). shadcn/ui на Base UI (style base-nova; по решению владельца вместо Radix — ради Combobox и Field), Tailwind v4, тема с золотым акцентом: тёмная по умолчанию, светлая, как в системе (свой ThemeProvider вместо next-themes, ключ tlh-theme, скрипт в index.html против вспышки). Каркас: Sidebar с иконками Lucide, шапка с переключателем темы, меню пользователя «Выйти»; экраны входа/«Нет доступа»/ошибки; API-клиент с X-CSRF-Token и обработкой 401/403 (перепроверка /api/me); TanStack Query; страница Главная (статистика, оформление бота, карточки разделов), остальные разделы — заглушки. Типы API общие через алиас @api → src/admin/apiTypes.ts. Скрипты в корне: pnpm build, pnpm dev:admin, pnpm check:admin; ADMIN_API_URL меняет адрес бота для прокси dev-сервера.

Этап 3: страницы настроек в admin-ui — Каналы и роли (+ голосовые роли), Логи (6 каналов, переключатели, тест), Оповещения, Приветствие (вкладки: в канале / в личку / прощание, предпросмотр «как в Discord» с подстановками и кнопками, пробные отправки), Липкие сообщения, Автоочистка. Общее: выбор канала/роли на Base UI Combobox (поиск, группы по категориям, цвет роли, предупреждение «выше роли бота», «Удалён с сервера»), useSectionForm (черновик, PUT /api/settings/:section, ошибки бота списком), панель «Есть несохранённые изменения», вопрос «Уйти без сохранения?» при переходе по меню и beforeunload, кнопки-подстановки {…} в текстах со счётчиком символов. API: в вариантах ролей появился color. Проверено на подставном API с настоящими getSettings/validateSettings поверх копии базы.

Этап 4: Расписание рег (новые реги, временная роль, живой список и события, архив через Select, расписания с днями недели на ToggleGroup и строкой-описанием), Шаблоны рег (карточки «Создать регу» с датой/временем и подтверждением, редактор шаблонов), Посещаемость (период, быстрые 7/30/90 дней, сводка, таблица с полосой посещаемости, поиск и сортировка), Опросы (список; редактор с номерами строк, проверкой на лету, переходом к строке ошибки, черновиком tlh-poll-draft, картинкой и подтверждением публикации; итоги: статистика по блокам с полосами, «По участникам» с поиском, CSV, копия, закрытие). Все страницы грузятся лениво (React.lazy), главный кусок ~400 КБ. Заглушка раздела удалена. Проверено на подставном API с настоящими parsePollFile/pollStats/answersByUser/summarize поверх копии базы.

Этап 5: server.ts отдаёт admin-ui/dist (hashed /assets — immutable, остальные GET → index.html, без сборки — страница «выполни pnpm build»), неудачный вход → /?login-failed; views.ts и HTML-маршруты удалены, server.test.ts переписан (3 теста: без сборки, сборка без перезапуска, вход/выход). Документация: development, deploy (pnpm build), guide, checklist (раздел «Новая админка»), README, CLAUDE.md. Проверено: pnpm typecheck, pnpm test 165/165, vp check, vp build; живой бот на :3000 отдаёт новую админку (экран входа, /api/me 401, ассеты 200). Осталось: вход через Discord владельцем и проверка сохранения вживую.
