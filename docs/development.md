# Для разработчиков

Как запустить бота, как он устроен и где что лежит. Руководство для участников и офицеров — в [guide.md](guide.md).

**Стек:** [Node.js](https://nodejs.org) 26+ (встроенные SQLite и Temporal, `.ts` запускается без сборки), TypeScript, [discord.js](https://discord.js.org) v14, [pnpm](https://pnpm.io). Веб-админка: сервер и API на [Hono](https://hono.dev) внутри бота, интерфейс — React + [shadcn/ui](https://ui.shadcn.com) (на [Base UI](https://base-ui.com)), Tailwind CSS и иконки [Lucide](https://lucide.dev), сборка [Vite+](https://viteplus.dev).

## Запуск

Нужны Node.js 26 или новее и pnpm (`npm install -g pnpm`, если его ещё нет).

### 1. Приложение в Discord

1. Открой [Discord Developer Portal](https://discord.com/developers/applications) → **New Application**.
2. На вкладке **General Information** скопируй **Application ID**. Это `CLIENT_ID`.
3. На вкладке **Bot**:
   - нажми **Reset Token**. Это `DISCORD_TOKEN_GUILD` в `.env`. **Никому его не показывай**, а если он утёк, сбрось ещё раз;
   - включи **Server Members Intent** (приветствие, лог входов и выходов) и **Message Content Intent** (фильтр мата, лог сообщений), затем **Save Changes**.
4. На вкладке **OAuth2** (нужно для входа в админку):
   - нажми **Reset Secret** и скопируй **Client Secret** в `DISCORD_CLIENT_SECRET`;
   - в **Redirects** добавь `http://localhost:3000/auth/callback` и сохрани.
5. Необязательно — **Света** (ИИ-персонаж): отдельное приложение «Света» с включённым **Message Content Intent**, его токен — `SVETA_TOKEN`, ключ Google Gemini из [AI Studio](https://aistudio.google.com) — `GEMINI_API_KEY`. Подробнее — в [руководстве](guide.md#офицерам-света).

### 2. Настройка

```bash
pnpm install
```

```bash
pnpm build
```

`pnpm install` ставит зависимости и бота, и интерфейса админки (папка `admin-ui`), `pnpm build` собирает интерфейс в `admin-ui/dist` — сам бот сборки не требует. Без сборки бот работает, а вместо админки показывает подсказку «выполни `pnpm build`».

Скопируй `.env.example` в `.env` и заполни токен, `CLIENT_ID`, `GUILD_ID`, `DISCORD_CLIENT_SECRET` и `SESSION_SECRET` (длинная случайная строка, команда для генерации есть в `.env.example`). Каналы и роли удобнее выбрать потом в админке.

### 3. Команды и запуск

Сначала пригласи бота на сервер по ссылке (её выводит `pnpm dev` при запуске, а `pnpm deploy` — при ошибке «Missing Access»), затем:

```bash
pnpm deploy
```

```bash
pnpm dev
```

В **Настройках сервера → Роли** перетащи роль бота **выше** ролей «Гость» и тех, кого он должен модерировать. Для «лог-сервер» и «лог-модерация» роли бота нужно право **«Просматривать журнал аудита»**, для «кто кого пригласил» — **«Управлять сервером»** (только оно открывает счётчики приглашений), для событий Discord по регам — **«Создавать события»**, для `/tempchannel` — **«Управлять каналами»** — оно есть в ссылке-приглашении; если бот уже на сервере, включи его роли вручную или пригласи бота по новой ссылке.

Открой админку: **http://localhost:3000** (адрес выводится в консоль) → «Войти через Discord». Войти могут те, у кого на сервере есть право «Управлять сервером». Если `DISCORD_CLIENT_SECRET` или `SESSION_SECRET` не заданы, бот работает без админки и пишет об этом в консоль.

При первом запуске бот сам загрузит 49 родных иконок WoW (классы, спеки, роли и шапка реги) как свои эмодзи: почти все — с wowhead, круглые значки ролей и ведущего — из [assets/role-icons](../assets/README.md). В консоли это строка `🎨 Иконки WoW: 49/49`. Если какая-то не загрузилась, бот попробует снова при следующем запуске.

### После обновления кода

Что выполнить после `git pull` или своих правок (бот при этом должен быть остановлен или перезапущен):

| Что поменялось | Команда |
| --- | --- |
| зависимости (`package.json`, `pnpm-lock.yaml`) | `pnpm install` |
| админка (`admin-ui/`) | `pnpm build` |
| описание слэш-команды (название, параметры, описание, права) | `pnpm deploy` |
| код бота (`src/`) | перезапустить бота; `pnpm dev` перезапускается сам |

Если не уверен, что поменялось, — выполни всё по порядку: `pnpm install`, `pnpm build`, `pnpm deploy`, перезапуск. Лишний раз это ничего не ломает. На сервере — то же самое, см. [deploy.md](deploy.md#6-обновить-бота).

### 4. Проверка

- **Рега:** `/raid open-now` сразу создаст реги в обоих каналах, ждать полуночи не нужно. Чтобы проверить напоминание «за час», создай `/raid quick` со временем через 1 час 3 минуты и запишись.
- **Приветствие:** зайди на сервер со второго аккаунта.
- **Опрос:** `/poll template`, затем `/poll create` с этим файлом.
- **Фильтр мата:** напиши что-нибудь нецензурное со второго аккаунта.
- **Логи:** в админке → «Логи» выбери каналы логов, сохрани и нажми «Тест в лог-каналы».

- **[assets/raid-banner.jpg](../assets/README.md)** — баннер вверху реги.
- **[src/raids/classes.ts](../src/raids/classes.ts)** — классы и спеки WoW Forever; **[src/raids/emojis.ts](../src/raids/emojis.ts)** — иконки ролей и шапки реги.

## Как это работает

### Бот — это программа, которая держит соединение с Discord

```
 Компьютер или сервер                       Discord
┌─────────────────┐   WebSocket (Gateway)   ┌──────────────┐
│  node index.ts  │ ◄────── события ─────── │              │
│  (discord.js)   │                         │   серверы,   │
│                 │ ──── HTTP-запросы ────► │   участники  │
└─────────────────┘ (ответить, кикнуть, …)  └──────────────┘
         │
         ▼
   data/bot.db  ← настройки, реги, записи, опросы, ответы (переживают перезапуск)
```

- `client.login(token)` открывает постоянное соединение (**Gateway**). Через него Discord **присылает события**: «зашёл участник», «новое сообщение», «нажата кнопка»…
- Чтобы **что-то сделать**, бот отправляет HTTP-запросы: `channel.send()`, `member.roles.add()` и т.п.
- Бот онлайн, пока программа запущена. Для работы 24/7 его запускают на сервере (VPS).

### Intents — на что бот подписан

В [src/index.ts](../src/index.ts) перечислены группы событий, которые бот хочет получать: серверы, участники, сообщения, голосовые каналы, модерация (журнал аудита) и приглашения. Два из них привилегированные и включаются вручную в Developer Portal: **Server Members** (вход и выход участников) и **Message Content** (текст сообщений для фильтра мата и лога сообщений). Там же включены **partials** — чтобы получать события и про то, чего нет в памяти бота (удаление старого сообщения, выход участника).

### Слэш-команды живут на стороне Discord

У каждой команды есть **описание** (`data`: имя, параметры, права) и **обработчик** (`execute`). Описание отправляется в Discord командой `pnpm deploy`, и Discord по нему показывает подсказки, когда пишешь `/`. Когда команду вызывают, приходит событие `interactionCreate`, и бот запускает нужный `execute`.

### Кнопки, меню и формы

У каждой кнопки, меню и формы есть `customId` — строка, которую Discord вернёт боту при нажатии. Бот кладёт туда всё, что нужно знать: `raid:spec:12` — «выбор спека в реге №12», `poll:submit:3:1` — «отправлен блок 1 опроса №3». [src/events/interactionCreate.ts](../src/events/interactionCreate.ts) смотрит на первую часть (`raid`, `poll`, `welcome`, `role`) и передаёт нажатие нужному модулю ([src/components.ts](../src/components.ts)). Поэтому кнопки продолжают работать и после перезапуска бота.

На каждое нажатие нужно ответить за **3 секунды**, иначе Discord покажет «Приложение не отвечает». Поэтому бот сначала отвечает человеку, а потом спокойно перерисовывает регу.

### Как выглядят сообщения

- **Рега** — embed в стиле Raid-Helper ([src/raids/render.ts](../src/raids/render.ts)). Колонки — это «поля» embed'а: Discord ставит по три поля в ряд, поэтому танки, ближний и дальний бой идут первым рядом, лекари — под танками. Баннер — отдельный embed сверху.
- **Приветствие и опросы** — Components V2: контейнер с цветной полоской, текст, картинка, кнопки внутри.

### Формы опросов

Одна страница опроса — это **модальное окно** (форма) Discord с вопросами блока, максимум 5. Бот сам выбирает элемент: до 10 вариантов — кружочки или галочки, больше — выпадающий список. Discord не позволяет открыть следующую форму сразу после предыдущей, поэтому между блоками показывается личная карточка с кнопкой «Продолжить». Вопрос `Ответ: картинка` — поле загрузки файла: бот проверяет тип и размер, скачивает картинку и хранит её в таблице `poll_files` (ссылки Discord на вложения со временем перестают работать). Кнопки опроса работают и в личке — так проходят анкету новичков, присланную в личные сообщения. Опрос можно сохранить и без публикации (админка, `POST /api/polls` с `publish=0`): у него нет канала и сообщения (`channelId: null`, в базе — пустая строка, т. к. `channel_id NOT NULL`), его проходят только по кнопке `poll:start:<id>` из приветствия и лички; закрытие тогда ничего не перерисовывает.

### Расписание и напоминания

[src/raids/scheduler.ts](../src/raids/scheduler.ts) проверяет базу и часы (по Киеву, с учётом перехода на летнее и зимнее время). Реги по расписанию он открывает в начале каждой минуты (время открытия всегда ЧЧ:ММ, так рега появляется в первые секунды), а раз в 30 секунд рассылает напоминания, зовёт на сбор и закрывает запись. Реги открываются по строкам расписания шаблонов рейдов ([src/raids/slots.ts](../src/raids/slots.ts)): строка — «рейд в такой-то день и время ← рега открывается в такой-то день и время», рейд всегда не дальше недели после открытия (`daysAfterOpen`), `dueOpenings` отдаёт реги, которым пора открыться, с ключом `<шаблон>:<дата рейда>`. Шаблоны читаются из настроек на каждом тике, так что изменения из админки подхватываются сразу. Старые расписания (дни открытия + сдвиг) переносятся в шаблоны при чтении настроек. Если у шаблона включено `dmOnOpen`, после открытия (`openScheduledRaids` и «Создать регу сейчас» в админке) [openDm.ts](../src/raids/openDm.ts) `sendRaidToDms` в фоне рассылает регу в личку людям с ролями из `pingRoleIds`: по одному сообщению в `DM_PAUSE_MS` (1,5 с), рассылки идут друг за другом, итог — в лог. Кнопка `raiddm:off|on:<сервер>:<канал>:<сообщение>` (обрабатывается в `interactionCreate` вне сервера) пишет отписку в таблицу `raid_dm_optout`.

**Виды сборов и лимиты.** [src/raids/kinds.ts](../src/raids/kinds.ts) — рейд, подземелье, PvP: название и слова для сообщений («на рейд» / «в подземелье», безличные глаголы), размер и лимиты по умолчанию. Лимиты танков, лекарей и бойцов хранятся в шаблоне и снимком в реге (`raids.kind`, `raids.limits`); `lineup()` раскладывает записи по очереди с учётом лимитов, `fullGroups` после кнопки роли подсказывает, что эта роль уже набрана. Группы от игроков — команда [/group](../src/commands/raids/group.ts) по настройкам `settings.groups` (правила — [src/raids/groups.ts](../src/raids/groups.ts)), отметка `raids.player`: у них нет события Discord, оповещений офицерам, посещаемости и временной роли. Отмена, перенос и новое время начала — общие `cancelRaid`, `moveRaid`, `newStart` в [service.ts](../src/raids/service.ts).

**Кто может записаться.** Роли «в основу» и «только в запас» копируются из шаблона в регу (`raids.main_role_ids`, `raids.reserve_role_ids`), запись проверяется по ролям участника ([src/raids/lineup.ts](../src/raids/lineup.ts), `signupAccess`), а отметка `raid_signups.reserve` держит гостя в запасе. Там же `lineup()` — единый расчёт основы, запаса и «под вопросом» для реги, итога, «Сбор!» и посещаемости. Всё сделанное отмечается в базе, поэтому перезапуск ничего не задваивает. Если бот был выключен в момент открытия, рега откроется, как только он включится (в течение 6 часов).

### Настройки

[src/botSettings.ts](../src/botSettings.ts) хранит всё, что меняется из админки, одним JSON в таблице `settings`. Значение собирается так: умолчания из кода ← ID из `.env` ← сохранённое в базе. Код читает настройки через `getSettings()` в момент использования, а не при запуске, — поэтому сохранение в админке действует сразу.

### Лог бота

[src/lib/botLog.ts](../src/lib/botLog.ts) с самого запуска (`captureConsole()` в `src/index.ts`) копирует всё, что бот пишет через `console.log/info/warn/error`, в таблицу `bot_log` (последние 5000 строк, цвета терминала убираются) и отмечает запуск. Падение процесса записывается через `uncaughtExceptionMonitor` — поведение Node при этом не меняется; обрывы и восстановление связи с Discord пишутся из событий shard в `src/index.ts`. Админка показывает это на странице «Лог бота» (`GET /api/botlog?level=all|warn|error&q=…&before=<id>`). Чтобы что-то появилось в логе, достаточно `console.log`/`console.warn`/`console.error`.

### Света

[src/sveta/](../src/sveta) — ИИ-персонаж. Это второе подключение к Discord внутри того же процесса (`startSveta()` в `src/index.ts`): свой токен `SVETA_TOKEN`, свой бот-аккаунт с урезанными правами (`SVETA_PERMISSIONS`: видеть, писать, читать историю, реакции). Без токена Света просто не подключается.

- [triggers.ts](../src/sveta/triggers.ts) — когда отвечать: упоминание, ответ на её сообщение, имя (в начале, после запятой или приветствия; «свет погас» не считается), изредка сама.
- [context.ts](../src/sveta/context.ts) — последние 15 сообщений канала → переписка для модели: люди как «Имя: текст» (подряд идущие склеиваются), её реплики — от модели; ответ чистится от «Света:» и живых @everyone.
- [gemini.ts](../src/sveta/gemini.ts) — `generateContent` по REST через `fetch` (ключ — в заголовке `x-goog-api-key`), мягкие фильтры безопасности, у Gemini 3 низкое «обдумывание»; ошибки сводятся к `quota | rate | auth | model | blocked | busy | unavailable` (429: `rate` — квота PerMinute или только RetryInfo, `quota` — PerDay; `busy` — 5xx; `unavailable` — таймаут 30 с, сеть, прочее). `generateSteady` идёт по `readyModels` (выбранная, потом `FALLBACK_MODEL` = `gemini-flash-lite-latest`, кроме отдыхающих в `ModelRest`): при `busy` — один повтор через 2 с, потом модель отдыхает (`restMs`: сбой — 5 мин, `rate` — retryDelay в пределах 10 с…5 мин, `quota` — час) и запрос идёт к следующей; ключ/фильтр/нет модели — сразу наверх. Все отдыхают — `index.ts` не стучится в Gemini (вердикт `paused`). Каждая попытка — запрос в счётчике; сбои пишутся в строку ответа, текст 429 — в лог.
- [limits.ts](../src/sveta/limits.ts) — пауза для одного человека, потолки в час и в день (счётчик дня по Киеву — в таблице `sveta_usage`, там же число запросов к Gemini), «перерыв», когда все модели отдыхают (`paused`, решает `index.ts` по `ModelRest`).
- [persona.ts](../src/sveta/persona.ts) — характер по умолчанию и правила чата, которые добавляются к характеру из админки всегда.
- [tools.ts](../src/sveta/tools.ts) — что Света знает о гильдии: `guildSummary` (три ближайшие реги — в каждой инструкции) и инструменты `upcoming_raids`, `raid_roster`, `raid_schedule` (только чтение базы этого сервера). Если модель просит инструмент, бот выполняет его и спрашивает ещё раз — не больше двух кругов, на последнем инструменты выключены (`toolMode: NONE`). Ответ модели с вызовом возвращается в переписку целиком (с `thoughtSignature` Gemini 3), на каждый вызов — один `functionResponse` с тем же `id`.
- [memory.ts](../src/sveta/memory.ts) — память о людях в таблице `sveta_people`: отношение (−100…+100), прозвище, до 10 заметок. Досье собеседников (`dossiers`) лежит в инструкции. Инструменты `remember`, `change_attitude`, `set_nickname` пишут только об авторе сообщения (это задаёт код, а не модель): шаг отношения ±20, не больше трёх записей за ответ; если в ответе модели есть текст и только записи в память, второго запроса нет. «Что ты обо мне помнишь» и «забудь меня» (`memoryCommand`) обрабатывает код без Gemini. Админка: `GET/PUT/DELETE /api/sveta/people`.
- Файл историй (кнопки «Скачать / Загрузить истории» в админке) — [admin-ui/src/lib/lore.ts](../admin-ui/src/lib/lore.ts): `loreFile`, `parseLoreFile` (свой формат `{ kind: "sveta-lore", lore }` или просто массив), `mergeLore` (тот же человек по любому имени — обновить, новый — в конец, ничего не удалять); тесты — `src/sveta/loreFile.test.ts`.
- [lore.ts](../src/sveta/lore.ts) — истории о людях от офицеров (`settings.sveta.lore`: имена/ники + текст). В инструкцию попадают только истории тех, кого назвали в последних сообщениях или кто в них пишет (`matchLore`: целое слово с окончанием до трёх букв, без учёта регистра и «ё»), не больше пяти. Модель их только читает.
- [news.ts](../src/sveta/news.ts) — новости о сборах заготовленными фразами (без Gemini) в канал `sveta.newsChannelId`: открытие реги (`publishRaid`), «Сбор!» (планировщик), перенос и отмена (`moveRaid`, `cancelRaid`).

Настройки — `settings.sveta` (страница «Света» в админке), состояние — `GET /api/sveta/status`.

### Логи

[src/logs/](../src/logs) пишет в 6 каналов (какой канал и включён ли — из настроек):

| Канал | Откуда события |
|---|---|
| лог-дискорда | вход и выход участников ([members.ts](../src/logs/members.ts)) |
| лог-сообщения | удаление, изменение, массовое удаление ([messages.ts](../src/logs/messages.ts)) |
| лог-голос | вход, выход, переход ([voice.ts](../src/logs/voice.ts)) |
| лог-сервер | журнал аудита: каналы, роли, ники, роли участников, настройки сервера ([auditLog.ts](../src/logs/auditLog.ts)) |
| лог-рейдов | действия игроков на регах ([raids/actionLog.ts](../src/raids/actionLog.ts)) |
| лог-модерация | команды бота ([lib/modlog.ts](../src/lib/modlog.ts)) + журнал аудита: ручные кики, баны, тайм-ауты |

«Кто кого пригласил» ([invites.ts](../src/logs/invites.ts)): бот помнит счётчики использований приглашений и при входе новичка ищет то, у которого счётчик вырос.

**Оповещения офицерам** ([alerts.ts](../src/logs/alerts.ts)) идут в отдельный канал с упоминанием роли: поздние отписки ([raids/handlers.ts](../src/raids/handlers.ts)) и посещаемость ([raids/attendance.ts](../src/raids/attendance.ts) — сверка записей с теми, кто в голосовом; результат сохраняется в таблицу `raid_attendance` для будущей статистики). «Сбор!», проверку посещаемости и снятие временной роли рейда ([raids/tempRole.ts](../src/raids/tempRole.ts), отметка `role_cleaned`) и архив прошедших рег ([raids/archive.ts](../src/raids/archive.ts), отметка `archived`) запускает планировщик рег.

Журнал аудита — единственный источник, где Discord говорит, **кто** сделал действие. Записи, где исполнитель — сам бот, пропускаются: команды бота пишут в лог сами, а выдача ролей с кнопок была бы шумом. Сообщения, удалённые фильтром мата, не дублируются в «лог-сообщения».

### Админка

Две части в одном репозитории:

- **Сервер** — [src/admin/](../src/admin): [Hono](https://hono.dev) в том же процессе, что и бот, поэтому видит кэш бота (каналы и роли для выпадающих списков) и ту же базу. Он отдаёт собранный интерфейс из `admin-ui/dist` (все адреса вроде `/channels` или `/polls/5` получают `index.html` — дальше разбирается само приложение) и JSON API на `/api` ([api.ts](../src/admin/api.ts)). Типы ответов API — [apiTypes.ts](../src/admin/apiTypes.ts), общие для сервера и интерфейса.
- **Интерфейс** — [admin-ui/](../admin-ui): React-приложение на компонентах [shadcn/ui](https://ui.shadcn.com) (Base UI), стили Tailwind, иконки Lucide, данные через TanStack Query. Тёмная тема по умолчанию, переключатель — в шапке. Страницы — `admin-ui/src/pages`, общие формы и выбор канала/роли — `admin-ui/src/components`.

Как это защищено:

- **Вход** ([auth.ts](../src/admin/auth.ts)): Discord OAuth2 со scope `identify` → сессия в подписанной cookie на 7 дней. Право «Управлять сервером» на сервере `GUILD_ID` API перепроверяет на каждом запросе: без входа — 401, без права — 403.
- **CSRF:** изменяющие запросы к API должны нести заголовок `X-CSRF-Token` с токеном из сессии (интерфейс берёт его из `GET /api/me`).
- Каждое сохранение и действие (пробная отправка, публикация опроса, создание реги) пишется в «лог-сервер».
- Слушает только `127.0.0.1`. Для работы на VPS: обратный прокси с HTTPS (например, Caddy), `ADMIN_URL=https://домен` и такой же Redirect в Developer Portal.

**Разработка интерфейса:** запусти бота (`pnpm dev`) и в другом окне `pnpm dev:admin` — откроется http://localhost:5173, изменения видны сразу. Запросы `/api`, `/login`, `/auth`, `/logout` уходят к боту на порт 3000 (другой адрес — переменная `ADMIN_API_URL`). Войди один раз на http://localhost:3000 — cookie общая для обоих портов. Компоненты shadcn добавляются командой `npx shadcn@latest add <имя>` в папке `admin-ui`. Перед коммитом — `pnpm check:admin` и `pnpm build`.

## Структура проекта

```
src/
├── index.ts, config.ts, settings.ts, botSettings.ts, db.ts, components.ts
├── commands/        ← слэш-команды (general, moderation, roles, raids, polls)
├── events/          ← события: ready, interactionCreate, guildMemberAdd, profanityFilter
├── logs/            ← лог-каналы: участники, сообщения, голос, журнал аудита
├── admin/           ← сервер админки: вход через Discord, JSON API, раздача admin-ui/dist
├── welcome/         ← приветствие и кнопка «Гость», памятка в личку, прощание
├── raids/           ← классы/спеки, иконки, вид реги, кнопки, планировщик, база
├── polls/           ← формат файла опроса, формы, итоги, база; service.ts — публикация и закрытие (общие для /poll и админки)
└── lib/             ← общее: время, фильтр мата, журнал модерации, ссылка-приглашение, голосовые роли, липкие сообщения, оформление бота
admin-ui/            ← интерфейс админки (React, shadcn/ui, Vite+): pages/ — страницы, components/ — формы и выбор каналов
docs/                ← руководство (guide.md), проверка по шагам (checklist.md), бот на сервере (deploy.md) и этот файл
deploy/              ← служба systemd и настройка Caddy для сервера
examples/poll-example.txt  ← пример опроса
assets/                    ← баннер реги
```

## Как добавить свою команду

1. Скопируй [src/commands/general/ping.ts](../src/commands/general/ping.ts), например в `src/commands/general/roll.ts`, и поменяй имя, описание и `execute`.
2. Допиши её в список в [src/commands/index.ts](../src/commands/index.ts).
3. Выполни `pnpm deploy`; `pnpm dev` перезапустится сам.
